# スピーク招待リンク掲載と PR 表記基盤の設計

作成日: 2026-07-20

## 背景と目的

本サイトに英会話アプリ「スピーク」の友達招待リンクを掲載する。
運営者の個人サイト (necofuryai-personal-website) には招待リンクを載せた `/pr` ページが既にあり、本サイトにも同じリンクを置きたい。
ただし本サイトは技術ブログであり、収益リンクの掲載は記事の信頼を損なわない範囲にとどめる。

将来は Amazon アソシエイトなどのアフィリエイトプログラムへの加入も見込む。
そのため、スピーク単体の対応ではなく、収益リンクを含むページに共通して使える開示の仕組みを併せて整備する。

## 調査結果の要点

設計に先立ち、法規制と各プログラムの要件を調査した (2026-07-20 時点)。

**景品表示法のステルスマーケティング規制**:
規制の処分対象は広告主 (事業者) であり、個人ブロガーは対象外である。
友達招待リンクを名指しした規定はなく、自主的に書いた紹介記事は「事業者の表示」に該当しない可能性が高い。
ただし招待側に報酬が入る以上、PR 表記を付けるのが実務上の安全ラインとされる。
表記は「PR」「プロモーションを含みます」などの文言を、ページ冒頭の視認しやすい位置に明瞭に置く必要がある。
末尾への配置や小さい文字は、消費者庁の運用基準が不明瞭な例として挙げている。

**スピーク友達紹介プログラム**:
ブログへの掲載を禁じる規定は公式ヘルプにも利用規約にもない。
現行条件は、被招待側が登録から 7 日以内に年間プランを Web 決済すると 1,000 円割引、招待側は 30 日の審査後に 1 人あたり 2,000 円である。
条件は予告なく変更されうるため、掲載時には時点の断り書きが要る。
招待リンク経由の登録では、登録者のメールアドレスの一部が紹介者に見える仕様である。

**Amazon アソシエイト (将来加入時の前提)**:
公式の審査要件は「10 件以上のオリジナル投稿」と「おおむね 60 日以内の更新」である。
転載や広告中心でオリジナリティのないサイトは公式の却下例に明記されており、リンクを並べただけのページは不利に働く。
加入時には参加表記のメインページ掲載と、プライバシーポリシーでのデータ収集開示が規約上必須となる。

**技術ブログ界隈の慣行**:
受け入れられるのは、実体験に基づくレビューで欠点も書き、リンクを記事末に置く形である。
リンクの羅列や冒頭の購入導線は嫌われる。
Google はアフィリエイトリンクに `rel="sponsored"` を推奨している。

## 掲載形式の決定

掲載形式は体験記事型とする。
スピークを実際に使った体験記事を書き、記事末に招待リンクを置く。

独立した紹介ページ (個人サイトの `/pr` の移植) も検討したが、採用しない。
リンクを置くだけの薄いページは技術ブログの中で浮き、Amazon アソシエイトの審査でもマイナス材料になるためである。
体験記事であれば、記事自体が審査要件の「オリジナル投稿」に数えられる。

## スコープ

今回実装するのは次の 4 点である。

1. frontmatter フラグ `promotion` の追加
2. PR 表記コンポーネントの新規作成
3. 収益リンクに `rel` 属性を自動付与する rehype プラグインの新規作成
4. プライバシーポリシーへの開示追記と、体験記事の雛形作成

Amazon アソシエイト加入時の作業 (参加表記のフッター掲載など) は今回のスコープ外とし、末尾に加入時のチェックリストとして記す。
ナビゲーションバーは変更しない。

## 詳細設計

### frontmatter フラグ `promotion`

`src/content.config.ts` の postsCollection スキーマに `promotion: z.boolean().optional().default(false)` を追加する。
既存の `draft` フラグと同じイディオムであり、フラグを付けた記事だけに PR 表記が表示される。

### PR 表記コンポーネント

`src/components/PromotionNotice.astro` を新規作成する。
表示文言は「本記事はプロモーション (紹介リンク) を含みます」とする。

表示位置は `src/pages/posts/[...slug].astro` の PostMetadata 直後とする。
記事タイトル直下のファーストビュー内であり、運用基準の求める「冒頭・明瞭」の要件を満たす。
スタイルは本文と同等の可読性を保ち、小さすぎる文字や薄い色を避ける。

### rehype プラグイン rehype-sponsored-links

`src/plugins/rehype-sponsored-links.mjs` を新規作成する。
指定ドメインへの外部リンクに `rel="sponsored nofollow noopener"` と `target="_blank"` を付与する。

ドメインリストは `astro.config.mjs` からプラグイン引数で渡す。
初期値は `app.usespeak.com` のみとし、Amazon 加入時に `amzn.to` と `www.amazon.co.jp` を追加する。
相対リンクと内部リンクは対象外とする。

この方式により、記事執筆時は Markdown のリンク記法だけで済み、`rel` 属性の付け忘れが起きない。
収益リンクのドメイン管理も一箇所に集約される。

### プライバシーポリシーへの追記

`src/content/spec/privacy.md` に「広告・紹介リンクについて」の節を追加する。
記載内容は次の 3 点である。

- 一部の記事に紹介リンク (友達紹介プログラムのリンク) を含むこと
- 紹介リンク経由の登録により運営者に特典が入ること
- 該当記事には冒頭に PR 表記を付けること

将来のアフィリエイトプログラム参加表記も、この節に追記する。

### 体験記事の雛形

`pnpm new-post speak-review` で記事の雛形 (`src/content/posts/speak-review.md`) を作成し、`promotion: true` と `draft: true` を設定してコミットする。
記事の構成は次のとおりとする。

1. 英語学習の背景
2. スピークの使い方と体験 (運営者が執筆する)
3. 良かった点と合わなかった点
4. 招待リンクと注意事項

注意事項は admonition ディレクティブ (`:::note`) で記述し、次の内容を含める。

- 割引の条件 (登録から 7 日以内、年間プラン、Web 決済のみ)
- 2026 年 7 月時点の条件であり変更されうること
- 登録者のメールアドレスの一部が紹介者に共有されること

`draft: true` の間は本番ビルドから除外されるため、雛形のままコミットしても公開ページと UI smoke に影響しない。
dev サーバーでは draft 記事も表示されるため、PR 表記とリンク属性の動作確認は雛形のまま行える。

## 検証計画

- `pnpm check` と `pnpm build` が通ること
- dev サーバーで draft 記事を開き、PR 表記がタイトル直下に表示されること
- ビルド成果物の HTML で、招待リンクに `rel="sponsored nofollow noopener"` が付与されていること
- `promotion` フラグのない既存記事の表示が変わらないこと
- UI smoke (`pnpm test:ui`) がローカルで通ること

記事の体験パートを執筆して `draft` を外す公開時には、トップとアーカイブを desktop / mobile / dark で目視し、UI smoke を通す。

## Amazon アソシエイト加入時のチェックリスト (将来)

- 参加表記「Amazon のアソシエイトとして、〔名称〕は適格販売により収入を得ています。」をフッターに掲載する (メインページ掲載が規約要件)
- `privacy.md` の「広告・紹介リンクについて」に参加の事実とトラッキングの開示を追記する
- `rehype-sponsored-links` のドメインリストに `amzn.to` と `www.amazon.co.jp` を追加する
- リンクはアソシエイトツールが生成したものを改変せず使う (リダイレクタでのラップはクローキング扱いのリスクがある)
- 公式の画像リンクは廃止済みのため、商品リンクはテキストリンクを基本とする
- 申請前にサイトが「10 件以上のオリジナル投稿」と「60 日以内の更新」を満たしていることを確認する
- 審査期間の適格販売 3 件について、自己購入と家族や友人への依頼購入は規約違反であることに留意する
